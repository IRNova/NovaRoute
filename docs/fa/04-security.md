# ۴. امنیت و سخت‌سازی

این سند «چه کار کنم» است. اگر دنبال «چه چیزی خراب بود و چطور درست شد» هستید، [گزارش ممیزی](05-security-report.md) را بخوانید.

## مدل تهدید در یک نگاه

`NovaRoute` سه چیز ارزشمند را در یک جا نگه می‌دارد:

1. **اعتبارنامهٔ ارائه‌دهنده‌ها** (کلید `API`، توکن `OAuth`، کوکی نشست). سرقت این‌ها یعنی خرج کردن پول شما و دسترسی به حساب‌های شما.
2. **محتوای مکالمه‌ها** که ممکن است شامل کد، داده و راز مشتری باشد.
3. **دسترسی اجرایی روی سرور**، اگر عامل `Nova` و ابزار ترمینالش فعال باشد.

مهاجم‌های محتمل، به ترتیب احتمال:

| مهاجم | مسیر ورود | چه چیزی جلویش را می‌گیرد |
|---|---|---|
| اسکنر خودکار اینترنت | پورت باز، `‎/v1` و `‎/setup` | کلید اجباری دروازه، دروازهٔ تنظیم اولیه، مسدودسازی خودکار `IP` |
| همسایهٔ شبکه یا کاربر دیگر سرور | `loopback`، فایل‌های `DATA_DIR` | مجوز فایل‌ها، رمزگذاری میدانی |
| صفحهٔ وب مخرب در مرورگر مدیر | `CSRF` و `CORS` به `localhost` | کوکی `SameSite=Lax`، بررسی `Origin`، کلید اجباری |
| تزریق دستور غیرمستقیم به عامل | پیام `Telegram`، محتوای صفحهٔ وب | صف تأیید انسانی، طبقه‌بند دستور فقط‌خواندنی، سقف تأیید در ساعت |
| کسی که به پشتیبان‌ها دست دارد | `DATA_DIR/db/backups` | مجوز فایل، رمزگذاری میدانی |

## فهرست سخت‌سازی

### حداقل‌های ضروری

- [ ] تنظیم اولیه را بلافاصله بعد از نصب کامل کنید. تا وقتی رمزی ذخیره نشده، پنل «بی‌صاحب» است.
- [ ] `JWT_SECRET` و `API_KEY_SECRET` و `MACHINE_ID_SALT` مقدار تصادفی داشته باشند (`openssl rand -hex 32`).
- [ ] `Require API Key` روشن بماند و هر کلاینت کلید جدا بگیرد.
- [ ] `chmod 600` روی `.env` و `DATA_DIR/db/data.sqlite`.
- [ ] `ADMIN_MASTER_PASSWORD` بعد از استفاده حذف شود.
- [ ] یک دامنه و `TLS` (اسکریپت نصب با `Caddy` این کار را می‌کند). بدون آن، رمز و کلیدها روی شبکه متن ساده‌اند.

### توصیه‌شده

- [ ] به‌جای رمز مشترک، برای هر نفر حساب جدا با کمترین نقش لازم بسازید (`Settings > Security > Users`). کسی که فقط گزارش می‌خواهد `viewer` بگیرد، نه `admin`.

- [ ] ورود دومرحله‌ای (`TOTP`) را روشن کنید.
- [ ] اگر فقط از یک ماشین استفاده می‌کنید، `HOSTNAME=127.0.0.1` بگذارید و از `SSH tunnel` یا `Tailscale` استفاده کنید؛ در این حالت پورت اصلاً روی اینترنت نیست.
- [ ] دسترسی داشبورد از روی تونل عمومی را ببندید.
- [ ] برای کلیدها تاریخ انقضا بگذارید.
- [ ] `ENABLE_REQUEST_LOGS` را روی سرور مشترک خاموش نگه دارید.
- [ ] پشتیبان روزانه را به یک مقصد خارج از سرور منتقل کنید (فایل پشتیبان همان اعتبارنامه‌ها را دارد؛ رمزگذاری‌شده نگهش دارید).

### اگر عامل `Nova` را روشن می‌کنید

- [ ] فقط شناسهٔ گفتگوی خودتان به‌عنوان `adminChatId` ثبت شود.
- [ ] ابزار `terminal` را فقط برای عاملی روشن کنید که واقعاً به آن نیاز دارد.
- [ ] «تأیید خودکار دستورهای فقط‌خواندنی» را اگر لازم ندارید خاموش کنید (`Nova Bot > Tools`).
- [ ] سقف تأیید در ساعت (`maxApprovalsPerHour`) را کم نگه دارید.
- [ ] هیچ‌وقت عاملی که پیام غریبه‌ها را می‌خواند (`Instagram`، حساب کاربری `Telegram`) با ابزار `terminal` یا `files` ترکیب نکنید. تزریق دستور غیرمستقیم دقیقاً از همین‌جا شروع می‌شود.

## ابزار بررسی وضعیت

```bash
cd /opt/novaroute
node scripts/nova-security-audit.mjs          # انگلیسی
node scripts/nova-security-audit.mjs --fa     # فارسی
node scripts/nova-security-audit.mjs --json   # برای CI
```

ابزار `.env`، تنظیمات پایگاه‌داده و مجوز فایل‌ها را می‌خواند و گزارش می‌دهد: رمز نداشتن پنل، رازهای ضعیف، دروازهٔ باز، اعتبارنامه‌های رمزنشده، دسترسی داشبورد از تونل و مجوزهای بازِ فایل. اگر یافتهٔ بحرانی باشد با کد خروج `1` تمام می‌شود، پس می‌شود آن را در زنجیرهٔ استقرار گذاشت.

## مرزهای دسترسی که نباید دست‌کاری شوند

هنگام کار روی کد، این چند نقطه ساختار امنیتی را نگه می‌دارند:

| نقطه | چرا مهم است |
|---|---|
| `custom-server.js` | نشانی `IP` را از سوکت `TCP` می‌گیرد و هدرهای جعلی را حذف می‌کند. محدودسازی نرخ و تشخیص «محلی» روی این بنا شده. |
| `src/dashboardGuard.js` | سیاست پیش‌فرض بستهٔ `/api/*`. هر افزودن به فهرست عمومی یعنی یک مسیر بدون احراز هویت. |
| `src/lib/nova/safeCommand.js` | تنها چیزی که بین عامل و پوستهٔ `root` ایستاده است. سست کردن الگوها یعنی برگرداندن یک آسیب‌پذیری بحرانی. |
| `src/lib/security/urlGuard.js` | نگهبان `SSRF`. |
| `src/lib/auth/timingSafe.js` | مقایسهٔ رازها. |
| `src/lib/apiKeyPolicy.js` | سیاست هر کلید: فعال بودن، دسترسی مدل، سقف هزینه و سقف نرخ. |
| `src/lib/security/keyRateLimiter.js` | پنجرهٔ لغزان سقف نرخ و هم‌زمانی. |
| `src/lib/auth/roles.js` | ماتریس نقش‌ها؛ سست کردنش یعنی دادن اختیار `admin` به بقیه. |

## ثبت رخداد و پایش

از این نسخه، هر تغییر مدیریتی ثبت می‌شود: `Settings > Security > Audit Trail` یا `‎/api/security/audit`. در بررسی حادثه، اولین جایی است که باید نگاه کنید (چه چیزی عوض شد، از کدام `IP`، با نشست یا با توکن `CLI`).

سنجه‌ها هم از `‎/api/metrics` قابل جمع‌آوری‌اند. یک هشدار ساده که ارزشش را دارد: جهش ناگهانی `novaroute_key_cost_usd_total` روی یک کلید، یعنی آن کلید یا لو رفته یا کلاینتش حلقه افتاده است.

## پاسخ به حادثه

اگر فکر می‌کنید سرور دستکاری شده:

```bash
# ۱. همهٔ نشست‌ها را باطل کنید (Settings > Security > Log Out Everywhere)
#    یا مستقیم: رمز را عوض کنید؛ همین کار نشست‌ها را می‌چرخاند.

# ۲. کلیدهای دروازه را باطل کنید
#    Dashboard > API Keys → حذف یا غیرفعال‌سازی

# ۳. مهم‌ترین گام: کلید همهٔ ارائه‌دهنده‌ها را در پنل خودشان باطل کنید
#    (OpenAI, Anthropic, ...) — پنل NovaRoute نمی‌تواند این را برایتان انجام دهد.

# ۴. رازهای محلی را بچرخانید
openssl rand -hex 32   # JWT_SECRET جدید
openssl rand -hex 24   # API_KEY_SECRET جدید (توجه: مقادیر رمزشدهٔ قبلی خوانا نمی‌مانند)
rm -f /var/lib/novaroute/auth/cli-secret

# ۵. رد پا را ببینید
journalctl -u novaroute --since "7 days ago" | grep -Ei "unauthorized|401|403|blocked"
```

سیاهه (`audit`) ابزارهای عامل در فضای نام `novaTools` پایگاه‌داده است و دستورهای اجراشده و تصمیم‌های تأیید را نگه می‌دارد.
